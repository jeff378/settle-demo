# 정산 차액 분석기 — 데모

플랫폼 정산 명세서와 내부 매출 기록을 대조해 **차액의 원인을 자동으로 찾아 분류하는** 웹앱 데모.

> 회사에서 쓰는 기존 코드를 열지도 참조하지도 않고 처음부터 새로 작성했습니다.
> 화면의 플랫폼·고객명·금액은 전부 가상이며, 샘플 모드에서는 상단에 "가상 데이터" 띠가 고정 노출됩니다.

## 구조
```
index.html   전부 여기에 있습니다 (HTML + CSS + JS 인라인)
```
외부 요청은 Pretendard 폰트와 SheetJS(엑셀 파싱·생성) 두 개뿐입니다.
**업로드한 파일은 어디로도 전송되지 않고 브라우저 안에서만 읽힙니다.**

## 매칭 엔진 — 5단계

| 단계 | 조건 | 실패하면 |
|---|---|---|
| 1 | 이름 + 금액 + 날짜 정확 일치 | ↓ |
| 2 | 이름 유사도 ≥ 0.75 + 날짜 일치 (금액은 달라도 됨 → 오기재로 잡힘) | ↓ |
| 3 | 그룹 합산 — 명세서 여러 줄의 합 = 내부 한 줄 (연박·다인실) | ↓ |
| 4 | 날짜 허용범위 ±3일 확장 (월말↔월초 이월) | ↓ |
| 5 | 미매칭 분류 + 원인 라벨 부여 | — |

**2단계의 함정** — 같은 이름의 명세서가 여러 줄이고 그 합이 내부 금액과 맞으면,
2단계에서 한 줄만 집어가지 않고 **3단계로 넘깁니다.** 그러지 않으면 그룹 합산이 영영 발동하지 못합니다.

### 이름 유사도가 흡수하는 것
- 성·이름 순서 차이 — `이서연` ↔ `서연 이`
- 부분 마스킹 — `최준호` ↔ `최*호`
- 중복 표기 — `신유겸` ↔ `신유겸신유겸`
- 그 외 편집거리 기반 유사도 75% 이상

## 원인 라벨

| | 라벨 | 판정 조건 |
|---|---|---|
| 🟠 | 오기재 | 매칭됐는데 금액이 다름 |
| 🟠 | 취소처리 누락 | 내부에만 있음 (기간 내) |
| 🟠 | 중복예약 오류 | 내부에 동일 건이 2번, 명세서엔 1번 |
| 🟠 | 매출 미반영 | 명세서에만 있고 비고가 비어 있음 |
| 🟢 | 이월 가능성 | 내부에만 있고 체크아웃이 기간을 넘거나 체크인이 기간 끝 2일 이내 |
| 🟢 | 취소수수료 | 명세서에만 있고 비고에 취소/수수료/위약 |
| 🟢 | 폴리오 통합 | 3단계 그룹 합산으로 매칭됨 |

### 설계 원칙
`총 차액 − Σ(원인별 기여분) = 미설명 잔액`

원인 분류가 정확하면 미설명 잔액이 **0원**이 됩니다.
"대충 맞다"에서 멈추지 않고 여기까지 밀어붙이는 것이 이 도구의 핵심입니다.

## 검증

매칭 엔진의 계산을 Node로 검증합니다. `<script>` 블록에서 1~6절(데이터 + 엔진)만 떼어내
샘플 데이터로 돌리고, 합계·원인별 금액·단계별 건수·개별 판정을 기대값과 대조합니다.

```bash
node verify.js
```

> 이 방식으로 실제 버그 2건을 잡았습니다 — ① 2단계가 그룹 합산 후보를 먼저 집어가
> 3단계가 발동하지 못하던 문제 ② 1·2단계가 날짜를 보지 않아 4단계가 발동하지 못하던 문제.

## 배포
```bash
vercel --prod --yes
```

## 규칙
- 회사 코드·실데이터·회사명을 열거나 참조하거나 포함하지 않습니다
- 실존 플랫폼 상호를 쓰지 않습니다 — "플랫폼 A / B / C"로 일반화
- 샘플 데이터는 전부 가상이며 "가상 데이터" 라벨을 유지합니다
